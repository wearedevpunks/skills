# Delivery family

This family takes one accepted spec, issue or plan to closeout. `$delivery-phase` routes one bounded goal through one durable phase at a time; each phase emits a common Phase Result and the router recomputes the next phase from durable evidence. Three gates guard every dispatch: Architecture/SPEC Pair Complete, Backlog Projection Complete and Plan Complete; a gap, a missing or stale plan included, routes to `$requirements-phase`. Delivery has no plan phase: `$requirements-phase` owns `$create-plan` and `$swarm-planner` (see the requirements family) and retains `PLAN.md`; a plan amendment returns to it as plan-only input. `$implement-spec` is the parent: it dispatches scoped workers, applies Task Gates, and calls `$verify-behavior`, whose coverage gaps go to `$create-verification-skill` or `$update-verification-skill`. `$goalify` wraps an AFK run; `$handoff` carries a pause across sessions. `$orchestrator-phase` sits above this family when several cross-dependent scopes move at once: it starts `$delivery-phase` in Track threads and merges what they report ready.

`$requirements-phase` (retained `PLAN.md`) ─ result ─→ `$goalify` → `$delivery-phase` → `$implement-spec` → `$verify-behavior` → `$review-phase` → `$docs-ingest-phase` → closeout

## Inside AFK delivery

Inside AFK `$delivery-phase`, every skill in this family settles each pending user question as an [Autonomous Decision](../../delivery-phase/SKILL.md#afk), recorded in the Phase Result and in the skill's own log where it has one (`$implement-spec` `IMPLEMENTATION-NOTES.md`). Vendored inner skills (`$tdd`, `$verify-behavior`, `$create-verification-skill`, `$update-verification-skill`, `$agent-browser`, `$react-doctor`, `$debug-agent`) keep their human steps as written; the calling owned skill maps them: `$implement-spec` takes the plan's `tdd_target` as the confirmed interface, out-of-goal decision debt as an out-of-bounds decision, 2FA as missing access and the delivery base when `$react-doctor` finds no upstream; `$debugging-phase` runs `$debug-agent` reproduction and verification itself. Only missing access stops for the human. Standalone use keeps each skill's human gates.

## `$delivery-phase`
Explicit-only; Pack `planning`. AFK router that takes one bounded delivery goal through one durable phase at a time.
- **Use when:** an accepted spec, issue or plan needs delivery. Modes: Full delivery (end to end), Resume, HITL checkpoint (one phase, then stop), Closeout. **Not for:** a runtime failure with no active delivery, which goes to `$debugging-phase`; unclear requirements, which go to `$requirements-phase`.
- **Steps:** router, first match; each phase is done when it emits a valid Phase Result. 1 Resolve required Context Pointers (one bounded refresh, else `blocked`). 2 Keep a terminal `human_steering_required` (missing access only). 3 Pair Complete gate before any dependent dispatch, also local and resumed work; gap → `phases/spec.md` → Requirements Phase. 4 Failed task → `references/failure-continuity.md`. 5 Read `pass_count` from `review.mjs status`: `review_due` → `phases/review.md`, `debug_active` → `phases/debug.md`, `repair_active` → `phases/implement.md`. 6 Backlog Projection Complete gate; gap → Requirements Phase. 7 Plan Complete gate (plan retained with a verified immutable blob URL); missing/stale plan → `phases/spec.md` → Requirements Phase, delivery creates no plan; open plan work → `phases/implement.md` (`$implement-spec`). 8 Completed implementation → `phases/review.md` until a valid Pass Report covers the delivery. 9 Docs-affecting → `phases/docs-ingest.md` (`$docs-ingest-phase`), else `phases/closeout.md`.
- **Calls:** `$implement-spec`; `$review-phase` (Full delivery invokes it at once; other modes persist `review_due` + invocation context and stop, naming `$review-phase` in the stop report and asking nothing); `$debugging-phase` only for runtime evidence in scope; `$write-backlog` delivery status; `$docs-ingest-phase`; `$repo-asset-management` for UI evidence. **Called by:** human; a `$goalify` goal; an `$orchestrator-phase` Track brief, or its message after `grill closed`; briefs from `$design-phase` and `$resolve-debt-phase` tell the human to invoke it.
- **Orchestrated Track:** when the brief names an Orchestrator thread, AFK holds unchanged; the Track sends one line per state change (each out-of-bounds Autonomous Decision, each stop report, the closeout exit), never acks. Closeout sends `ready <PR URL> @ <head commit>` when PR Watch reports the head `mergeable`, and asks the human for no merge review; the Orchestrator merges. A new head sends a new `ready`.
- **Writes:** Delivery Handoff (`references/phase-handoff.md`); Phase Result `phase, outcome (complete|blocked|failed|skipped|human_steering_required), authority_or_evidence_created, changed_facts, invalidated_evidence, next_eligible_phase, blocker_or_stop_reason, context_pointers`; review/repair projection states `review_due … clean_handoff` with `pass_report` and `review_run_id` (pass count derived from `review.mjs status`, never stored); human-steering access record; debt artifact keyed by (Pass Report path, finding ID); closeout path-limited commit.
- **Stops / gates:** AFK in every mode and inner step, Requirements Phase included: each pending user question becomes an Autonomous Decision (recommended answer, marked in-bounds or out-of-bounds, recorded in the Phase Result's `changed_facts` and the Delivery Handoff's `autonomous_decisions`); never `AskUserQuestion`, `request_user_input` or another question tool. Changed requirements, a weaker gate, a redesign, `human_steering_required` review routes and `review_budget_exhausted` take out-of-bounds decisions; each one is posted to the thread at once under `⚠️ AUTONOMOUS DECISION OUTSIDE ACCEPTED BOUNDS`, and the closeout report and the PR body's Autonomous Decisions Block (closeout writes it above the `$pr` Managed Region) open with the full list. Only missing access → `human_steering_required`. One plan creates at most one pull request per Touched Repository; split or stack PRs only when the user explicitly asks. Every phase commits to that repository's branch and PR. Design-Owned UI Code from a `$design-phase` promote commit is accepted input: delivery adds logic, data and the rest of the requirement; a change to a design-owned file is a defect fix only, recorded in the Phase Result. Stops at a written HITL boundary, reported closeout, or `human_steering_required` (missing access only). Review: one pass by default; a second only for architecture, security/authz, public contract, runtime/deploy topology or accepted-scope change (`--accepted-risk`); at two → a third pass only on words the human already wrote in the goal or thread (`--human-direction`; delivery asks for none); otherwise an out-of-bounds Autonomous Decision captures open findings as debt and continues. Ordinary repair → Focused Repair Validation, rerun only invalidated Verification. `$review-phase` runs every Code Review; docs and closeout need a valid Pass Report. Closeout: release classification when the final tree changed, push, CI per check (local broad run only when CI lacks the full suite/E2E), merge is never deployment evidence, Fog completion needs production evidence, PR Watch until the open PR reports for its current head, Owned Stack teardown, then the test-resource sweep. Resume wording alone never grants Full delivery.
- **Source:** `.agents/skills/delivery-phase/SKILL.md`, `phases/router.md`, `phases/{spec,implement,review,debug,human-steering,docs-ingest,closeout}.md`, `references/{artifact-state,context-continuity,phase-handoff,failure-continuity}.md`

## `$implement-spec`
Model-invoked; Pack `planning`. Implements an agent-ready spec folder through a plan-derived Execution Frontier; the parent coordinates and scoped workers edit.
- **Use when:** a retained pair and an execution-ready `PLAN.md` exist. **Not for:** a missing or invalid plan, which routes to `$requirements-phase`; Code Review, which `$review-phase` owns.
- **Steps:** 1 Resolve the spec folder; pair gate; load `<wiki-root>/AGENTS.md`, `ARCHITECTURE.md`, `SPEC.md`, `PLAN.md`, notes, existing debt items. 2 Seed `IMPLEMENTATION-NOTES.md`. 3 Compute the Execution Frontier; reserve Active Write Scopes; dispatch workers with the worker brief, guidance forwarded unchanged. 4 Apply each Task Result's Task Gate (`passed | repair_required | blocked`) at once; recompute the frontier. 5 Review each change with `$codebase-design` vocabulary. 6 After the first meaningful pushed commit, reuse or create one draft PR per Touched Repository. 7 In-goal debt now; out-of-goal decision debt → tiny `$requirements-phase`. 8 Provider-task facts → `$write-backlog` delivery status + readback. 9 UI evidence via `$repo-asset-management`; `runtime_validation: required` needs conclusive public-entrypoint proof. 10 `$verify-behavior` verify for visibly exercisable acceptance (stories the plan changes). 11 Acceptance audit `met | unmet | blocked`, Manual Review Checklist, finalize, `$show-me` presentation. Done when `SPEC.md` `status: implemented` and `PLAN.md` `**Status:** Complete`, only with every criterion met and architecture closure passed.
- **Calls:** `$tdd` (every testable task RED first); `$codebase-design`; `$simplify` on changed code; `$verify-behavior`; `$create-verification-skill` on Uncovered Surface (wait for `ready` + Reference Smoke Proof); `$update-verification-skill` on Uncovered Behavior (`unchanged|updated` resume, `blocked` keeps criteria blocked, `product-failure` → debugging); `$debugging-phase` on verify mismatch; `$agent-browser` for `review_mode` browser/mixed; backend/frontend-domain-structure before the first architecture wave; `$requirements-phase` plan-only input for execution-only architecture amendments. **Called by:** `$delivery-phase` (`phases/implement.md`).
- **Writes:** `<spec-folder>/IMPLEMENTATION-NOTES.md` (Execution and Reconciliation, Skill Application Evidence, UI Evidence Links, Runtime Validation Evidence, Behavior Verification Evidence, Acceptance Criteria Status, Manual Review Checklist `Area|Check|How to perform|Expected result`); `PLAN.md` status, log, RED/GREEN evidence (parent only); one tech-debt file per item `<wiki-root>/content/docs/project/tech-debt/<domain>/<spec>/<debt-slug>.md` for out-of-goal, human-decision or external-blocker debt (debt, why not now, decision/blocker, owner/next action; `$resolve-debt-phase` input); draft PR.
- **Stops / gates:** one plan creates at most one pull request per Touched Repository; split or stack PRs only when the user explicitly asks; every wave, repair and review fix lands on that repository's branch and PR. Every edit, repair included, is delegated; when the brief names a `$design-phase` promote commit, its Design-Owned UI Code is accepted input, each worker brief touching it carries that rule, and each defect fix to a design-owned file is recorded in `IMPLEMENTATION-NOTES.md`; capacity zero = capacity blocker; no worker branches or worktrees. An Active Write Scope stays exclusive until the old writer is proven stopped. Local validation is focused; CI owns broad regression. Verification Tiers: T1 receipts, T2 focused repro on the Owned Stack, T3 plan-scoped journey; a New Discriminator precedes any expensive rerun. Forgotten RED → `recovered`. A draft PR satisfies no gate. Returns to delivery only when all gates hold.
- **Source:** `.agents/skills/implement-spec/SKILL.md`, `references/{lifecycle,parallel-orchestration,parallel-worker-brief,validation-scope,runtime-product-validation,architecture-conformance,ui-screenshot-evidence}.md`, `assets/IMPLEMENTATION-NOTES-TEMPLATE.md`

## `$tdd`
Model-invoked; Pack `quality`. Test-drives behavior changes with vertical red-green through public interfaces.
- **Use when:** behavior-changing work, or an explicit TDD / RED-GREEN request. **Not for:** docs, formatting, generated code, config without asserted behavior, scaffold bookkeeping; test-only suite work goes to `$make-tsuite`.
- **Steps:** 1 Plan: classify `tdd_status` (`required | not_testable | recovered | not_applicable`), confirm interface + prioritized behaviors, `$codebase-design`, record `red_command / expected_red_failure / green_command`. 2 Tracer bullet: one test RED → minimal GREEN. 3 One test at a time; record `red_evidence` / `green_evidence`. 4 First-run pass → Sensitivity Proof in `sensitivity_evidence`; spec rules and example generalisations → properties.
- **Calls:** `$codebase-design`. **Called by:** `$create-plan` (RED targets), `$implement-spec` (workers), `$make-tsuite`.
- **Writes:** tests; evidence fields in `PLAN.md`.
- **Stops / gates:** Hard Law: no production code before RED. Mock only at system boundaries. HITL interface confirmation; inside AFK delivery the plan's `tdd_target` and task contract satisfy it and every other choice is an Autonomous Decision.
- **Source:** `.agents/skills/tdd/SKILL.md`, `high-signal-tests.md`, `mocking.md`, `properties.md`, `sensitivity.md`

## `$codebase-design`
Model-invoked; Pack `quality`. Shared vocabulary and method for deep modules, seams, adapters, leverage, locality and testable boundaries.
- **Use when:** designing interfaces or seams, testability, or another skill needs the vocabulary. **Not for:** discovery of refactor candidates, which `$improve-codebase-architecture` runs.
- **Steps:** apply the glossary and principles (one adapter = hypothetical seam, two = real seam; deletion test); classify dependencies in-process / local-substitutable / remote-owned / true-external; Design It Twice: frame, ≥2 alternatives, compare depth, locality, seam, test surface, migration cost, recommend.
- **Calls:** readonly subagents for alternatives. **Called by:** `$create-plan`, `$tdd`, `$implement-spec`, `$improve-codebase-architecture`, `$requirements-grill` (checkpoint, L3 derivation).
- **Writes:** `codebase_design_notes` in `PLAN.md`.
- **Stops / gates:** none.
- **Source:** `.agents/skills/codebase-design/SKILL.md`, `DEEPENING.md`, `DESIGN-IT-TWICE.md`

## `$simplify`
Model-invoked; Pack `quality`. Refines recently modified code for clarity without behavior change.
- **Use when:** after writing code; before a code commit in HI. **Not for:** behavior changes, which go through `$tdd`.
- **Steps:** review current branch changes or the named scope; apply Names, Combine related concepts, Derivability, Scope. Done when behavior is unchanged and checks still pass.
- **Calls:** none. **Called by:** `$implement-spec`.
- **Writes:** code in the named scope only.
- **Stops / gates:** none.
- **Source:** `.agents/skills/simplify/SKILL.md`

## `$verify-behavior`
Model-invoked; Pack `verification`. Drives the real product through project-owned references and returns falsifiable evidence.
- **Use when:** `$implement-spec` invokes `verify`; `$debugging-phase` invokes `reproduce`. **Not for:** Code Review (`$review-phase`), coverage repair (`$create-verification-skill` / `$update-verification-skill`), acceptance classification (the caller).
- **Steps:** 1 Select: read caller checks, identities, mode; cover only stories the caller's plan changes; read `references/README.md`, the app `README.md` and `features/README.md`; done when the selection trace is complete or a gap returns (missing app = Uncovered Surface, missing drive path = Uncovered Behavior). 2 Exercise: record Channel `browser | computer-use | cli`; freeze identities; reuse the caller's Owned Stack after controlled reset or Launch; complete the Observation Manifest before the first Drive; Doctor before Drive; drive end to end; record Scenario Falsifier and Relevant Negative Condition; owned cleanup. 3 Result.
- **Calls:** project references only. **Called by:** `$implement-spec`, `$debugging-phase`.
- **Writes:** evidence only. Project-owned files live under `.agents/skills/verify-behavior/references/` (`<app>/README.md` with Launch, Doctor, Drive, Evidence, Cleanup, Feature Map; `<app>/features/*`). Expectation classes: `invariant` and `output semantics` gate, `speculative` observes.
- **Stops / gates:** verify → `verified | partially verified | not verified | blocked`; reproduce → `confirmed | partially confirmed | not reproduced | blocked`. Uncovered gaps keep checks `blocked`; the caller owns repair. No invented tools, URLs or recordings; human auth stays with the user.
- **Source:** `.agents/skills/verify-behavior/SKILL.md`

## `$create-verification-skill`
Model-invoked; Pack `verification`. Creates and proves the missing project app reference on an Uncovered Surface.
- **Use when:** `$implement-spec` hits an Uncovered Surface. **Not for:** gaps in an existing app reference, which `$update-verification-skill` repairs.
- **Steps:** 1 Interview the repo: guidance, index, code, scripts, harnesses, wiki specs/flows; ask only for unobservable prerequisites (missing access → `blocked`; inside AFK delivery, others return to the caller, [Inside AFK delivery](#inside-afk-delivery)). 2 Author below `.agents/skills/verify-behavior/references/` on the delivery branch: index pointer, app `README.md` (CLI = build once + fresh session per Drive; server = one owned instance), `features/README.md` + selected features (Sub-features, How to get to it, Driving it, Gotchas, Observation Manifest). 3 Reference Smoke Proof: Launch → Doctor → one public Drive → evidence → Cleanup.
- **Calls:** none. **Called by:** `$implement-spec`.
- **Writes:** `.agents/skills/verify-behavior/references/README.md`, `<app>/README.md`, `<app>/features/*`.
- **Stops / gates:** `ready` only with full smoke proof, else `blocked`; control returns to `$implement-spec`; smoke proof is not acceptance; no product repair; shared ownership refused.
- **Source:** `.agents/skills/create-verification-skill/SKILL.md`

## `$update-verification-skill`
Model-invoked; Pack `verification`. Repairs selected executable coverage on an Uncovered Behavior; full Project Verifier audit only on explicit invocation.
- **Use when:** `$implement-spec` hits an Uncovered Behavior; an explicit full audit. **Not for:** a missing app, which goes back to `$implement-spec` for `$create-verification-skill`.
- **Steps:** 1 Select and reconcile: locate the app via the index; read wiki + source; preserve unrelated bytes; retire entries only with source + authority proof. 2 Drive and triage with live proof, Doctor before each session: reference drift, missing manifest (unsupported assertion → `speculative`), helper repair, Doctor drift (retry once), inaccessible state (blocked), wrong product behavior (`product-failure`).
- **Calls:** none. **Called by:** `$implement-spec`.
- **Writes:** files under `.agents/skills/verify-behavior/references/`; no separate maintenance PR.
- **Stops / gates:** exactly one of `unchanged | updated | blocked | product-failure`; never rewrites expected product semantics.
- **Source:** `.agents/skills/update-verification-skill/SKILL.md`

## `$repo-asset-management`
Model-invoked; Packs `planning`, `requirements`. Durable links for visual evidence and approved assets.
- **Use when:** screenshots, recordings or design assets need a stable URL. **Not for:** temporary paths or transient browser URLs as final evidence.
- **Steps:** 1 Prefer backlog attachments. 2 Fall back to repo-provider storage. 3 Provider from `.devpunks/settings.json`, else repo hints. 4 Load one provider reference (GitHub release, GitLab package, Azure blob, Bitbucket Downloads). 5 Return stable URLs + original filenames.
- **Calls:** none. **Called by:** `$implement-spec`, `$delivery-phase`, `$design-phase`.
- **Writes:** uploaded assets; returned URLs.
- **Stops / gates:** upload failure = recorded blocker, local path only as pending evidence; callers link this skill and copy no commands.
- **Source:** `.agents/skills/repo-asset-management/SKILL.md`

## `$orchestrator-phase`
Explicit-only; Pack `planning`. AFK Orchestrator that runs many cross-dependent scopes as Tracks across threads and repositories, merges and ships them, and reports to the human.
- **Use when:** several cross-dependent scopes of big size must land together (ordered merges, an optional integration branch, per-target deploys), typically from a home repository that holds guidance for every project involved. **Not for:** one scope, or small scopes: the Orchestrator goes solo and runs the routed phase itself.
- **Roles:** the **Orchestrator** is the one long-lived thread; it reports and never blocks on a question. A **Track** is a real thread per scope, started or adopted in its repository's project; the human talks to it only during a requirements grill. A **Worker** is a short-lived subagent for one triage, sweep, start check, smoke, deploy watch or post-deploy check; the Orchestrator's own Workers stay read-only, and a code change goes to the Track that owns the repository. A **Solo Thread** is what the Orchestrator becomes after it goes solo: it runs the routed phase under that phase's normal rules, so merging returns to the human.
- **Go solo:** the deciding invariant is cross-dependency between scopes, weighed with size. Many cross-dependent big scopes orchestrate; many small scopes, or one big scope, may go solo. Several PRs into one integration branch, each with its own deploys, always orchestrate. Whether the work fits one thread's context is no signal. Checked at Intake and when the last live Track settles.
- **Hosts:** the skill names Capabilities (spawn, fork, send, read, run a Worker, watch a PR, ask for a secret); `references/hosts.md` binds each to a host tool and ships the T3 Code binding. A host that cannot spawn or message threads goes solo. The Charter binds every other tool role per project: review gate, secret store, env manager, deploy targets and guard, git host.
- **Reports:** through `$wait-what`, three parts in order: Needs you (one line per item, led by a stable id such as `N3`, which the human quotes to answer), Changed since last report (state changes only), Running (each live Track and Worker). The first report also shows the Charter in short form.
- **Steps:** a router over `.orchestrator/<run>/ledger.md` and the new event. Intake (route; orchestrate or go solo; adopt) → Charter (`charter.md`, shown in the first report) → Split (Tracks and dependencies; integration branch only above about 1.5 million changed lines) → Spawn (brief; start check within 2 minutes) → Listen (steady state: one event, Ledger update, act or delegate, end the turn) → Merge (the exact reported commit, after the repository's checks and review; squash; restack) → Ship → Verify (post-deploy Worker) → Settle. A Solo Thread whose work grows reopens the phase through a fork plus `$handoff`.
- **Calls:** `$requirements-phase`, `$delivery-phase`, `$debugging-phase` inside Tracks (typed in the brief); Workers; `$handoff`; `$secrets-cli`; `$agent-browser`, `$verify-behavior`, `$model-checking`; `$wait-what` for reports. **Called by:** human.
- **Writes:** `.orchestrator/<run>/charter.md`; `.orchestrator/<run>/ledger.md` (Tracks, Needs-you items, decisions, events).
- **Stops / gates:** never a question tool; every pending choice is an Autonomous Decision. Human Gates: production deploys, new functional PR merges, paid infrastructure, production data deletion outside an approved migration; each waits as a Needs-you item while other Tracks continue. A gate opens on the human's words, typed or quoted in a relayed go that the Orchestrator checks against the source thread. Goes solo only when no live Track remains. Tracks report state changes to the Orchestrator ([Orchestrated Track](../../delivery-phase/SKILL.md#orchestrated-track)).
- **Source:** `.agents/skills/orchestrator-phase/SKILL.md`, `phases/router.md`, `phases/{intake,charter,split,spawn,listen,merge,ship,verify,settle,solo,reopen}.md`, `references/{hosts,ledger,charter,track-brief,report}.md`

## `$goalify`
Model-invoked; Pack `planning`. Turns messy intent into one lean `/goal`, activates it at once, and keeps working under it.
- **Use when:** an AFK or compaction-safe run needs one goal. **Not for:** planning the work itself, which the goal's named workflow does.
- **Steps:** read handoffs, specs, issues, logs, guidance; reduce to one objective with proof + stop; write the smallest goal (objective, context, workflow, proof, stop; pointer-heavy, no secrets, ≤4,000 chars); activate; report only progress, blockers, proof. Done when the goal is active and work continues.
- **Calls:** none; the goal text names `$delivery-phase`. **Called by:** human.
- **Writes:** the active goal.
- **Stops / gates:** the goal must state end-to-end delivery to select Full delivery. A delivery goal stops on closeout, a HITL checkpoint the human chose, or early only for missing access (`human_steering_required`); every other question, `review_budget_exhausted` included, is an out-of-bounds Autonomous Decision and the run continues ([Inside AFK delivery](#inside-afk-delivery)).
- **Source:** `.agents/skills/goalify/SKILL.md`, `EXAMPLES.md`

## `$handoff`
Model-invoked; Pack `planning`. Compacts the conversation into a handoff document for another agent.
- **Use when:** work pauses across sessions or agents. **Not for:** the `hi` Post-Command Handoff, which `$hi-cli` owns.
- **Steps:** write to the OS temp dir outside the workspace; delivery work follows the Delivery Handoff envelope; other work keeps next action, artifact pointers, blocker, unknowns, skill pointers; redact secrets. Done when the next action is provable, every pointer has identity + freshness, and completed vs remaining mutations are distinct.
- **Calls:** none. **Called by:** human.
- **Writes:** handoff file; returns its absolute path + a continuation prompt.
- **Stops / gates:** the receiver cold-routes; the Delivery Context Packet is never persisted.
- **Source:** `.agents/skills/handoff/SKILL.md`, `.agents/skills/delivery-phase/references/phase-handoff.md`
